# actions

iwamot's shared GitHub Actions composite actions.

## Actions

| Action | Purpose |
|--------|---------|
| `docker-build-digest` | Build a Docker image for a single platform by digest and upload it as an artifact. |
| `docker-merge-and-sign` | Merge per-platform digests into a manifest list, push it with semver and latest tags, then sign the image with cosign and attach an SBOM attestation. |
| `mise-validate` | Checkout caller repo, setup mise from `mise.toml`, and run `validate.sh`. |
| `npm-publish` | Checkout caller repo, install with `aube`, set version from tag, build, and publish to npm with provenance. |
| `uv-publish` | Checkout caller repo, build with `uv`, and publish to PyPI via Trusted Publishing. |

## Usage

Each action is invoked from a workflow step via `uses:`.

### `docker-build-digest`

Per-platform leg of a multi-arch Docker build. Builds the image, pushes to the registry by digest (no tag), and uploads the digest as an artifact so a downstream job can merge platform digests into a manifest list.

The caller must log in to the target registry before invoking this action. This action handles checkout internally, so the caller should not run `actions/checkout` before it.

Optional inputs:

- `file`: Path to the Dockerfile (default: `Dockerfile`).

```yaml
jobs:
  build:
    runs-on: ${{ matrix.runner }}
    permissions:
      contents: read
      # Registry login usually requires id-token: write (OIDC) or packages: write (GHCR).
    strategy:
      matrix:
        platform:
          - linux/amd64
          - linux/arm64
        include:
          - platform: linux/amd64
            runner: ubuntu-24.04
          - platform: linux/arm64
            runner: ubuntu-24.04-arm
    steps:
      # ... registry login ...
      - uses: iwamot/actions/docker-build-digest@<sha> # vX.X.X
        with:
          registry_image: ghcr.io/owner/repo
          platform: ${{ matrix.platform }}
```

### `docker-merge-and-sign`

Consumes per-platform digest artifacts (produced by `docker-build-digest`), pushes a multi-arch manifest list to the registry, then signs the image with cosign (keyless via OIDC) and attaches a SPDX-JSON SBOM as a signed attestation. By default, tags are generated by `docker/metadata-action` with `type=semver,pattern={{version}}`, and `latest` is added automatically by the action's `flavor: latest=auto` default.

The caller must log in to the target registry before invoking this action and must grant `id-token: write` for cosign's keyless signing.

Optional inputs:

- `tags`: Tags input forwarded to `docker/metadata-action` (default: `type=semver,pattern={{version}}`). Override when the action needs to run outside of a semver tag push (e.g., from a self-test workflow).

```yaml
jobs:
  merge-and-sign:
    runs-on: ubuntu-latest
    permissions:
      id-token: write
      # Additional permissions depend on the registry (e.g. packages: write for GHCR).
    needs:
      - build
    steps:
      # ... registry login ...
      - uses: iwamot/actions/docker-merge-and-sign@<sha> # vX.X.X
        with:
          registry_image: ghcr.io/owner/repo
```

### `mise-validate`

Expects a `mise.toml` with `min_version` at the caller's repository root and a `validate.sh` script. This action handles checkout internally, so the caller should not run `actions/checkout` before it.

```yaml
jobs:
  validate:
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - uses: iwamot/actions/mise-validate@<sha> # vX.X.X
```

### `npm-publish`

Install dependencies with `aube`, set the package version from the pushed tag (`refs/tags/vX.Y.Z` → `X.Y.Z`), build, and run `npm publish --provenance --access public`. This action handles checkout internally, so the caller should not run `actions/checkout` before it.

Expects the caller's `mise.toml` to provide `aube` (e.g. `npm:@endevco/aube`) and any node/bun toolchain its `aube run build` script needs. The caller must register the calling workflow as a Trusted Publisher on npm and grant `id-token: write` for OIDC provenance. A `production` environment is recommended at the caller's job level.

```yaml
name: Publish

on:
  push:
    tags: ['v*.*.*']

permissions:
  contents: read

jobs:
  publish-npm:
    runs-on: ubuntu-latest
    timeout-minutes: 5
    environment: production
    permissions:
      contents: read
      id-token: write
    steps:
      - uses: iwamot/actions/npm-publish@<sha> # vX.X.X
```

### `uv-publish`

Build the caller's package with `uv` and publish to PyPI via Trusted Publishing. This action handles checkout internally, so the caller should not run `actions/checkout` before it.

The caller must register the calling workflow as a Trusted Publisher on PyPI and grant `id-token: write` for OIDC. A `production` environment is recommended at the caller's job level.

```yaml
name: Publish

on:
  push:
    tags: ['v*.*.*']

permissions:
  contents: read

jobs:
  publish-pypi:
    runs-on: ubuntu-latest
    timeout-minutes: 5
    environment: production
    permissions:
      contents: read
      id-token: write
    steps:
      - uses: iwamot/actions/uv-publish@<sha> # vX.X.X
```
